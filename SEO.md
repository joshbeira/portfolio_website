# SEO

What is already in the repo, what you have to do by hand, and what is realistic.

## Realistic targets

Be clear about which fights are winnable, because effort spent on the others is wasted.

| Query | Realistic? | Why |
| --- | --- | --- |
| `josh beira` | **Yes — this is the goal** | Low competition, and the site is now the strongest entity signal for that name. |
| `josh beira warwick`, `josh beira machine learning` | **Yes** | Same, with the qualifier already in the title and schema. |
| `warwick racing machine learning`, `text-to-image person re-identification student` | **Plausible** | Long-tail, few pages compete. |
| `pdtbench`, `agentic trading benchmark` | **Plausible** | Near-unique terms; the project page is the only real result for the first. |
| `machine learning`, `AI`, `software engineering` | **No** | Wikipedia, Google, IBM and Coursera hold these with millions of backlinks and decades of authority. No portfolio ranks here, and no technique changes that. |

The honest version of "rank first for anything CS-related" is: **own your name completely, and rank
for the specific things you have actually built.** That is what this setup is aimed at.

## What is in the repo

- **`Person` schema** on the homepage (`index.html`, JSON-LD `@graph`) — the anchor for Google's
  entity understanding of "Josh Beira". Carries `sameAs` (GitHub, LinkedIn), `affiliation`,
  `alumniOf`, `worksFor`, `award`, and a long `knowsAbout` list. This is the single highest-value
  tag on the site for name search and for a future knowledge panel.
- **`WebSite`, `ProfilePage`, `ItemList`** alongside it, cross-linked by `@id`.
- **Per-project pages** under `/work/`, each with `SoftwareSourceCode` + `WebPage` +
  `BreadcrumbList` schema, a unique title and description, and a full write-up. Five extra
  indexable pages and five extra topic surfaces.
- **`robots.txt`** allows everything except `/tools/`, and explicitly welcomes answer-engine
  crawlers (GPTBot, ClaudeBot, PerplexityBot, OAI-SearchBot). Being cited in an AI answer for your
  name now matters roughly as much as a blue link.
- **`sitemap.xml`** — regenerated by `tools/build_work_pages.py`, so it cannot drift from reality.
- **Performance**: the hero photo went from a 293 KB 1200×1600 JPEG (which was *also* being served
  as the favicon) to a 13 KB WebP at display size, with a matching responsive preload. Real icon
  set + web manifest added.
- `max-image-preview:large` in the robots meta, so Google may show a large thumbnail.

## What you have to do — this is the part that decides it

On-page work gets you eligible. Links and profile consistency are what actually rank you.

### 1. Google Search Console (do this first)

Verified by the **HTML file** method. `googled2f802e0fa480847.html` sits at the repo root and is
served at <https://joshbeira.com/googled2f802e0fa480847.html>.

**Do not delete that file.** Google re-checks it periodically; if it disappears, verification is
revoked and you lose the property. It is 53 bytes and must stay byte-for-byte as Google issued it —
never reformat it, and never add a `noindex` or a robots rule that blocks it.

Remaining steps, in Search Console:

1. Hit **Verify** on the property (after the deploy has gone out).
2. **Sitemaps** → submit `sitemap.xml`.
3. **URL Inspection** → paste each URL → **Request indexing**. All seven:
   `/`, `/work/`, `/work/pdtbench/`, `/work/penny/`, `/work/byte-the-evidence/`,
   `/work/lambdagpt/`, `/work/covid-mortality-risk-model/`.

Check **Performance** monthly. It tells you the queries you actually appear for, which is the only
honest input to what to write next.

### 2. Bing Webmaster Tools

<https://www.bing.com/webmasters> — you can import directly from Search Console. Worth ten minutes:
Bing feeds ChatGPT search, so this is now an AI-visibility channel too.

### 3. Links pointing at the domain — the biggest remaining lever

Nothing here is optional if you want the name to be locked down. Each one is a signal tying the
entity "Josh Beira" to this domain.

- **GitHub profile** → set the *Website* field to `https://joshbeira.com`. Also add it to your
  profile README and to the *About* of every repo linked from the site. GitHub is a high-authority
  domain and this is the easiest link you will ever get.
- **LinkedIn** → website field, and put the URL in the About section as plain text too.
- **University of Warwick** → any departmental, society, or research-intern page that will list you.
  A `warwick.ac.uk` link is worth more than a dozen random ones.
- **Warwick Racing** → team page bio.
- **Devpost / hackathon pages** for the PDT hackathon, Hack the Law, and the Barclays challenge —
  add the site link and the project links.
- **`hey-penny.vercel.app`** → add a footer credit linking back.
- If the research turns into anything citable, **ORCID** and **Google Scholar** profiles, both
  linking here. These are strong `sameAs` targets and you should add them to the `Person` schema.

Use exactly `https://joshbeira.com` everywhere — same protocol, same spelling, no trailing variance.
Consistency is what lets Google merge these into one entity rather than several weak ones.

### 4. Keep the name consistent

The `Person` schema claims one name: **Josh Beira**. If you publish or get listed anywhere under a
different name, that work builds authority for a *different* entity and will not help this site. If
that ever becomes the case, add the other name to `alternateName` in the JSON-LD so Google links
them.

## Maintenance

**Adding or editing a project** — everything under `work/` is generated. Edit `PROJECTS` in
`tools/build_work_pages.py`, then:

```bash
python3 tools/build_work_pages.py    # rewrites work/**/index.html and sitemap.xml
```

Do not hand-edit the generated HTML; the next build overwrites it. Two things the generator does
*not* touch and you must update by hand:

- the `ItemList` in `index.html`'s JSON-LD,
- the matching `<article class="work-row">` block in `index.html`.

**After any content change**, resubmit the sitemap in Search Console (or just request indexing on
the changed URL — it is faster).

**Validate before pushing**:

- Rich results: <https://search.google.com/test/rich-results>
- Schema: <https://validator.schema.org/>
- Social previews: <https://www.opengraph.xyz/>

## Known gaps, in priority order

1. **No inbound links yet.** This is the whole ballgame. Section 3 above.
2. **Project pages share one `og:image`** (`/og.png`). Per-project cards would improve click-through
   when links are shared. `tools/og.html` is the template — open it, edit the text, screenshot at
   1200×630.
3. **No writing section.** Publishing genuinely gets you long-tail traffic that a portfolio cannot.
   One good post on something specific you have already done — the CLIP attribute-binding work, the
   50 ms perception budget — will outrank a lot of thin content. Only worth building if you will
   actually write.
4. **Placeholder results still missing.** `index.html` carries `TODO(josh)` notes where real metrics
   were removed for being fabricated. Filling those in with real numbers makes the pages more
   substantive and more citable. Do not re-add anything you cannot source from a real run.
